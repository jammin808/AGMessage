# AGMessage on the show network

AGMessage implements **Show Bus 1.2** (`docs/SHOWBUS.md`; master copy in Stagewatch). It is a `messenger` node.

| What | How |
|---|---|
| Hello | UDP 9928 every 2 s: `{"t":"messenger","v":1,"proto":1,"id":<stable 8 hex>,"ports":{"http":3023,"https":3023},"caps":["messages","action-prompts","documents","ai","context","receipts","proposals"],"clock":<unix ms>,"tls":"sha256:<hex>"}`. Not sent when bound to loopback. |
| HTTPS (§10) | The same port serves HTTP and HTTPS (a connection whose first byte is a TLS handshake is TLS). One self-signed ECDSA P-256 certificate per install, made with node:crypto (no new dependency, nothing put in the Windows certificate store), kept in `%LOCALAPPDATA%\AGMessage\tls.json` with its private key sealed; valid 825 days (Apple's limit) and renewed 30 days before it ends. `GET /tls` (how to trust it, the fingerprint) and `GET /tls.cer`. **Require HTTPS** (admin): plain HTTP and Socket.io only from this laptop — which is also how the Cloudflare tunnel connects. The admin cookie is `Secure` when set over HTTPS. |
| Peers | Every hello kind on 9928 (`main`, `agent`, `patterns`, `messenger`): live < 6 s, stale < 12 s, then dropped. Admin → Show network. |
| Stagewatch link | `GET ws://<sw>/ws` — or `wss://` when Stagewatch's hello carries `tls`, the address is `https://`, or a fingerprint is typed — with `Authorization: Bearer swk_…` (a **node**-scope key; never in the URL). Over TLS the certificate is fetched and checked first: against the pin for that node (`node:<id>` from its hello, else `url:<host>:<port>`), or before there is one against the hello's / typed fingerprint; nothing — the key above all — is sent to any other certificate. The first authenticated success pins it; a later change is refused as **CERTIFICATE CHANGED** (admin health line) until the admin accepts the new one. Ping `{"cmd":"ping","t"}` every 2 s → `{"type":"pong","t","t2","t3"}` gives the clock offset (best of 8; CLOCKS APART > 2 s). Stale after 6 s quiet, redial after 12 s, backoff 0.5 → 5 s with jitter. |
| Send to stage | `POST /api/message/<text>/<urgency>/off/ack` with `X-Request-Id: ag…`; reads the receipt `{"stage":"accepted"\|"applied","refs":{"messageId"}}`. The live frame's `messageId` / `messageAck` / `messageAckBy` then mark that message seen / acknowledged. A down link refuses at once (nothing queued). |
| Its context | `GET /api/context` (admin cookie, or `Authorization: Bearer agn_…` — the read-only token on the admin page). Show Bus §6 shape: meetings and people by role, open action-prompt questions, the Stagewatch link and clock, AI and tunnel state, role-level recent events, one-hop peers. **Never** message text, names, room names or codes, or documents. Posted to Stagewatch `POST /api/peers/context` on change and every 5 s while linked. |
| Stagewatch's context | `GET <sw>/api/context` on connect and every 5 s; shown on the admin page and given to the AI drafts as facts. |
| Show desk (§11) | When Stagewatch keeps the approval queue (`approvals` in its hello's caps, or `GET /api/proposals?from=` answers): the research team's 📝 on a message proposes it for the speaker's screen (`POST /api/proposals`, target `{"t":"main"}`, line `message "<text>" <urgency> ack`, risk `review`); its state (pending → approved / rejected → done / failed / undelivered, by whom, the result) is read every 3 s and shown on the message. AGMessage takes one verb from the desk: `notice <text>` (a notice to everyone in every open meeting, risk `review`, listed in its context's `commands`): approved ones are collected (`GET /api/proposals?target=<id>&state=approved`), run once through the normal path and reported (`POST /api/proposals/<id>/result`). |
| Health | `GET /api/health`: `{ok,version,uptime}` for anyone; restarts, last crash, watchdog give-up, event-loop delay (p50/p95/max), send-to-stage round trip, clock offset and save errors for the admin or the host laptop. |

## Without the internet

Everything above works on the local network alone. Only the AI drafts (Anthropic) and the Cloudflare tunnel need the
internet; when the AI can't be reached it says so and nothing else changes.
