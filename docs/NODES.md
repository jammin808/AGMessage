# AGMessage on the show network

AGMessage implements **Show Bus 1.2** (`docs/SHOWBUS.md`; master copy in Stagewatch). It is a `messenger` node. It
hears PlayMap's `playmap` kind (a Show Bus 1.3 proposal, PlayMap `docs/SHOWBUS-NODE.md`).

| What | How |
|---|---|
| Hello | UDP 9928 every 2 s: `{"t":"messenger","v":1,"proto":1,"id":<stable 8 hex>,"ports":{"http":3023,"https":3023},"caps":["messages","action-prompts","documents","ai","context","receipts","proposals","displays","help"],"clock":<unix ms>,"tls":"sha256:<hex>","build":"0.5.0+17.abc1234"}`. `build` is the build it runs (`app/lib/version.js`). Not sent when bound to loopback. |
| Peers | Every hello kind on 9928 (`main`, `agent`, `patterns`, `playmap`, `messenger`): live < 6 s, stale < 12 s, then dropped; a peer's `build` is kept when it is SemVer's alphabet within 64 characters. Admin → Show network. The hello is unauthenticated, so the table is bounded: at most 256 peers and 8 ids per address — a hello with a new id beyond that is dropped (and counted), while ids already heard keep refreshing — and its change reaches the admin page at most twice a second, latest wins. |
| HTTPS (§10) | The same port serves HTTP and HTTPS (a connection whose first byte is a TLS handshake is TLS). One self-signed ECDSA P-256 certificate per install, made with node:crypto, kept in `%LOCALAPPDATA%\AGMessage\tls.json` with its private key sealed; valid 825 days (Apple's limit) and renewed 30 days before it ends. `GET /tls`, `GET /tls.cer`. **Require HTTPS** (admin). |
| Stagewatch links | One per hall that has its own (the hall's Set up: address, `node`-scope key, fingerprint — kept sealed in `settings.json` → `hallStagewatch`, never in the room's own settings), and the default one (Admin → Show network) for every other hall. Each: `GET ws://<sw>/ws` (or `wss://` when Stagewatch announces a certificate, the address is `https://`, a fingerprint is typed, or the certificate is pinned) with `Authorization: Bearer swk_…` — never in the URL; the certificate checked against the pin for that node and for the link's own address before anything is sent — once pinned, a missing or spoofed hello never turns TLS off; removing a Stagewatch's address forgets its pins; ping every 2 s for the clock offset (CLOCKS APART > 2 s); stale after 6 s quiet, dropped at once and redialled after 12 s (backoff 0.5 → 5 s with jitter). A hall's frames reach only that hall's room and screens; a hall moved to another Stagewatch (or back to the default) tells its room and its screens at once. Saving a hall's Set up unchanged changes and records nothing. |
| Send to stage | `POST /api/message/<text>/<urgency>/off/ack` with `X-Request-Id: ag…` to the hall's Stagewatch; the receipt `{"stage":"accepted"\|"applied","refs":{"messageId"}}`; the live frame's `messageId` / `messageAck` / `messageAckBy` then mark that message seen / acknowledged. Sends and acknowledgements are keyed by link and message id (each Stagewatch numbers its own), and followed only while the link is on the Stagewatch the send went to: a link pointed elsewhere, or frames whose `seq` goes back (Stagewatch restarted, Show Bus §4), number afresh. The send keeps its link and its Stagewatch's address tag, so an AGMessage restart keeps following it. A down link refuses at once (nothing queued). |
| Show desk (§11) | When a hall's Stagewatch keeps the approval queue (`approvals` in its hello's caps, or `GET /api/proposals?from=` answers), a message can be asked of the operator with a destination (`app/lib/stagelines.js`): the speaker's screen `message "<text>" <info\|warn\|crit> off ack`; a role screen `signal message <moderator\|backstage\|interpreter> "<text>"`; a department its context has named since it was linked `signal message "<Dept>" "<text>"` (Stagewatch lists a department by its newest cue — kind `department` for a standby or GO, `cue` once messaged — so departments appear once Stagewatch has cued them this session); the operator alone `note "<text>"`. Only a destination the hall's Stagewatch offers, only urgency `info`/`warn`/`crit` (anything else is refused), and only a line Stagewatch's parser takes is proposed. The desk keeps 400 characters of a line, so a message asked for the speaker's screen is at most 377 characters (Send now takes 500). `POST /api/proposals` (target `{"t":"main"}`, risk `review`); its state is read every 3 s and shown on the message — `lost` when the desk no longer has it (it restarted, or the hall moved to another Stagewatch), never another proposal's of the same number (the line, the proposer and its time are compared). Every line is held to a port of Stagewatch's tokenizer and parser (0.4's `… <urgency> ack` was refused: Stagewatch reads the third word as the flash). AGMessage takes one verb from any desk: `notice <text>` (a notice in every open meeting, risk `review`), collected, run once — a restarted desk's new `p1` is a new proposal — and reported, the result posted again until the desk takes it (it lists a collected proposal only once). |
| Patterns and PlayMap | Linked by the admin (Admin → Show network → Link…) with the node's own pairing token, sealed in `settings.json` → `peerLinks`, optionally for one hall. `GET /api/context` every 5 s with `X-Patterns-Token` / `X-PlayMap-Token` (never in a URL; pinned TLS when the node announces a certificate, the address is `https://` or the node is pinned — a pinned node is never polled in plain HTTP): its light, headline, attention items and verbs on the halls board and in the AI's brief. A changed certificate is refused (red, CERTIFICATE CHANGED) until the admin accepts the one it presents (Admin → Show network → Accept certificate; audited); unlinking forgets the token and the pin. Driving it (`nodes.control`): a node linked for one hall by those with `nodes.control` in that hall; one linked for every hall only by those with it in every hall (and the admin), on the board too. Only a verb its context lists (the longest match), rated as the node rates the line: its listed risk, raised (never lowered) by the words the node says raise it (`riskWhen`, `highFor` — from its context, or PlayMap's `GET /api/verbs`, read once per connection), and a line that carries a line (`BIND ADD … TO <line>`, `BIND LEARN <line>`) at least the carried line's risk — high when it is JSON, quoted, unlisted or nested too deep. Low and review risk sent now — `POST /api/cmd` (one line; the request id as `X-Request-Id` for PlayMap, as the line's `@id ` prefix for Patterns) → its receipt (Patterns' `{"ok","msg"}` with its wire's `OK`/`ERR` words, HTTP 200 even for `ERR`; PlayMap's Show Bus receipt); high risk only proposed to the show desk of the node's hall (its own Stagewatch, else the default; the default for a node of every hall) — refused when that Stagewatch keeps none, never sent to another hall's (target `{"t":"patterns"\|"playmap","id"}`), where a person approves it and the node collects it with its own key. Every link and command is audited; never the token, and never a verb's secret words (`LINK PATTERNS <host> <token>`: the row keeps the line up to them, a receipt's words without them); a line carrying a secret is never proposed (the desk would keep it). PlayMap's `ASSISTANT SET enabled\|provider`, which it rates high but publishes nowhere yet, is rated high here too. |
| Its context | `GET /api/context` (admin, or `Authorization: Bearer agn_…` — the read-only token on the admin page). Show Bus §6: meetings and people by role, open action-prompt questions, the count of open help requests, each Stagewatch link and its clock (a hall's by the Stagewatch's own name), AI and tunnel state, role-level recent events, one-hop peers (a linked Patterns or PlayMap with its own light and headline). **Never** message text, names, room names or codes, or documents; at most 32 one-hop peers, live ones first. Each linked Stagewatch is posted (`POST /api/peers/context`, on change and every 5 s) the context of the halls that follow it — their meetings, prompts and help count, and its own link (a linked Patterns or PlayMap of another hall is left out); `GET /api/context` is the whole node. |
| Stagewatch's context | `GET <sw>/api/context` on connect and every 5 s, per link: the admin page, the AI's brief, and the departments offered as destinations. |
| Health | `GET /api/health`: `{ok,version,build,uptime}` for anyone; restarts, last crash, watchdog give-up, event-loop delay (p50/p95/max), send-to-stage round trip, clock offset and save errors for the admin or the host laptop. |

## Without the internet

Everything above works on the local network alone. Only the AI drafts (Anthropic) and the Cloudflare tunnel need the
internet; when the AI can't be reached it says so and nothing else changes.
