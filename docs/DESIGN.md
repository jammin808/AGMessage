# How AGMessage is built — speed, security and reliability

AGMessage runs a live event: a dropped message, a wrong screen or a leaked link happens in front of a room. It borrows
from two fields that live with that: **games** (many clients, unreliable networks, an authoritative server that must
never stall) and **medical device software** (every action traceable, every hazard tested, nothing claimed that was
not observed). This page says which practice is used where, so a change can keep it.

## From games: an authoritative server on an unreliable network

| Practice | Where |
|---|---|
| **Sequence numbers and deltas.** Every change to a room is an operation with a per-room number, a hall's Main room's and each side room's its own, and a page holds one room; a phone that drops off the Wi-Fi resumes with just what it missed, or a full snapshot when the gap is too old. One op table names the event each change is sent under, and the hall page applies a change it missed and one it hears live through the same row of its own table, so the two cannot draw it differently (Zulip applies one event stream to a fetched state and to live updates alike, [Zulip's events system](https://zulip.readthedocs.io/en/latest/subsystems/events-system.html)); a change the table cannot send is refused before it takes a number, so no page is left with a gap. | `lib/store.js` (`opsSince`, the ring), `lib/ops.js` (`UPD_EVENTS`, `applier`), `public/app.js` (`bump`, `rejoin`, `UPD_EVENTS`, `applyOp`) |
| **A send is said once.** Socket.IO delivers at most once; at least once needs a retry and a server that knows a repeat ([delivery guarantees](https://socket.io/docs/v4/delivery-guarantees)). So every write a page makes goes through one outbox, in the mode of what the person does. What a person wrote or answered gets a client id and is held while the page is not connected and joined, sent one at a time after the join's answer and again after a drop, with no time limit, and kept in the tab's own storage so a reload keeps it; the server answers a repeat of that id with what the first send became and commits nothing, as Matrix's transaction ids do ([client-server API](https://spec.matrix.org/latest/client-server-api/)), and a removed message's tombstone (the newest 500 per hall, in the snapshot too) answers it after a restart. What a person does to something is refused at once while the page is not connected, never sent late, and sent again after a drop only where the server answers a repeat; an answer that comes after its 5 s ("No answer") is shown too, so a slow Stagewatch's receipt is never lost. The sender's own screen says what is true: "◷ Sending" until the server has it, its composer holding its words until then, "△ Not sent" with the server's words, a send that landed before a reload matched to the message the page drew, and a message written offline marked with its wait for every reader, the AI's brief included (the time the page was not connected, not the time it queued behind another send or the rate). | `public/outbox.js`, `lib/store.js` (`sentAs`, `removed`, `gone`), `server.js` (`readSend`, `message`, `forward`, `react`, `delete`, `help:respond`), `public/app.js` (`drawHeld`) |
| **Back by itself.** A page is never left dead: a connection the server refuses for its rate carries when to try again (`retryMs`: never before the network's bucket holds its next token, at least 1 s, plus up to 2 s chosen at random so the pages behind one network do not come back in the same instant; 30 to 40 s for a place through the tunnel) and what it refused (`why`, in words that name the wait), and the page tries then, saying so in those words, while a refusal no wait lifts (HTTPS required) says `retry: false` and is never tried; after a drop Socket.IO tries again from 0.5 s, doubling to 2 s, each ±50 %, and a page shown again or back online that is not connected starts afresh at once instead of waiting out its backoff (Socket.IO's own `connect()` does nothing while it waits). A page down 2 s says so in words, never by colour alone; a screen the audience sees tries again in silence. A restart announces nobody: in its first 30 s a page naming a change its hall holds is one coming back, and the restart's own line says what happened. The watchdog's first restart waits 0.5 s, a step the Windows job's 20 kills in a row hold. Back on a new build, a page comes back as that build without cutting what a person is doing: each page names the build that served it as it connects, every answer it reads its server's build from carries the server's, and one on another build reloads itself at its own quiet moment, only while it is connected, so a reload never lands on a server it cannot reach (a hall page with nothing written and unsent and no act waiting on its answer, no dialog and no document on its stage, untouched for 5 s; the halls board likewise; a screen between takes, so no take on the air is cut; the admin page when its admin agrees), by itself once per build in a tab, onto scripts and styles the browser checks with the server at every load (no-cache, a 304 while unchanged) rather than the old build's from its cache. 0.5.1's pages, which name no build, are told to reload (`account:changed`) only once none of 0.5.1's files can still be fresh in a browser, 5 minutes after the start, so their reload brings the new build whole; a 0.5.1 screen cannot be, and "This laptop" names it. | `public/reconnect.js` (`AGM.reconnect`, `AGM.reconnect.build`), `server.js` (the connection's refusal, `join`'s `returning`, `/build.js`, `tellOld`, `pagesElsewhere`), `lib/guard.js` (`Bucket.waitMs`), `lib/resilience.js` (`SupervisorPolicy`) |
| **The server is the authority.** Identities are issued and signed by the server; a client never names itself, its role or its rights. Accounts' rights are read at connect and re-read when they change, and a browser signed in to an account joins as that account, never as a code guest. A seat has a limit, read before any right, the admin's included: On stage holds reading and writing messages and nothing else (no file, no question, nothing into another room, no screen, set-up, show network or draft, and no answer to someone else's help request: only its own Resolved), refused on the server whatever the page sends; the seat is the socket's, set at the join and moved only by the admin, and an upload token is checked against it again at use and ended in the tick the admin moves the page to a seat that shares no file. Rights are a room's: reading, writing and sharing files are asked of the room itself, by its scope (a hall's Main room by the account's halls, a side room only by the rooms the account is given, or the admin role), and refused when asked by a hall's code, so a check that names a room where a hall is meant fails closed rather than let an account of every hall in. | `lib/guard.js` (identities), `lib/rbac.js` (`SEAT_LIMITS`, `seatAllows`, `answersHelp`, `ROOM_SCOPED`, `canIn`, `guestCaps`), `lib/store.js` (`scopeOf`), `server.js` (`accountChanged`, `join`, `onStage()`, `allowed()`, `rightsIn`, `help:respond`) |
| **Latest wins for state, never a backlog.** Four frames of state go through one primitive, `Latest`: a change after a quiet window is sent on the next turn, the changes inside a window fold into one frame at its end, each with its newest state, and none is dropped — nothing is volatile, so the last change always arrives, and a page that stops reading is let go by the heartbeat. They are the halls board (300 ms), a hall's screens console (150 ms), its people list (100 ms) and its seen receipts (1 s, one frame per hall holding every receipt that moved), and health's `latest` says what each saved; a timer of its own in a handler file is counted by a test, each with its reason. A frame only reads the state, so one that faults while it is built is refused and counted in health's `handlerFaults`, as a handler's throw is, and the other halls' and watchers' frames still go. Outside it: `nodes:changed`, sent when a linked node's light changes or the admin links, unlinks or confirms one, and for the nodes heard on the network at most every 500 ms by their own coalescer; and Stagewatch frames, which replace each other, each sent when its view changes. The snapshot model: send the newest state, never a backlog ([Gaffer On Games](https://gafferongames.com/post/state_synchronization/)). | `lib/latest.js` (`Latest`, `sendEach`), `server.js` (`frames`), `lib/nodes.js` (`_changed`, `_set`), `test/resilience.test.js` (the timer count) |
| **Fewer frames, not smaller ones.** Frames are not deflated: a broadcast is framed once and that frame written to every socket of it, where per-message deflate compressed it again for each (Socket.IO ships it off for its cost in CPU and memory, [server options](https://socket.io/docs/v4/server-options/)); HTTP long-polling keeps HTTP compression. A join storm and a burst of receipts are one frame per window, not one per event to every page. | `server.js` (`perMessageDeflate`, `frames`) |
| **Liveness from silence.** A link is stale after 6 s without a frame and redialled after 12 s with jittered backoff; a screen's countdown dims to `--:--` rather than show a confident stale time. | `lib/nodes.js`, `public/display.js` |
| **Rate limits and lockouts per client.** Token buckets for messages, chatter, uploads, AI and screen reports — uploads per connection and per network, so joining again, opening more sockets or taking the next address refills nothing; lockouts for guessing codes, tokens and passwords. A bound per address counts a network (`limitKey`): through the tunnel an IPv6 address by its /64, which a mobile network gives each phone and within which the phone changes address (RFC 6459 §5.2, RFC 8981), so one phone never steps out of a bound by its next address; a venue address whole. The one bound that keeps the full address is the sign-in's own allowance and lock per address, because through the tunnel its lock per name holds for the whole tunnel. The buckets of connections, room lookups and uploads are bounded at 5,000 networks and never reset: the fullest go first, so a flood of new addresses hands no drained network its burst back. | `lib/guard.js` (`Bucket`, `Buckets`, `Lockout`, `limitKey`), `server.js` (`/api/upload`, the connection's gate, `join`, `/api/rooms/:code`, `/api/context`) |
| **The internet link.** Remote phones come through a Cloudflare Quick Tunnel, which takes 200 requests in flight and answers the rest 429 where AGMessage never hears of them; an open page holds one for as long as it lives. So the tunnel has 150 places (50 kept for page loads, files and uploads), one network half of them at most, and AGMessage refuses past them itself, in words that say what was refused and when the page tries again, which it does by itself. The number rests on the cautious reading that an open WebSocket counts against Cloudflare's 200, until reading 0's tunnel row (below) says; if it does not, the places become the largest fan-out reading 0 records with delivery p99 under 50 ms. The venue never waits for the tunnel. A place is for a page in a room: a socket that has not joined one within 20 s, and carries no account, admin token or screen link, gives its place back. Every refusal is counted per show day by kind in health and in the day's peaks (so a restart carries on from them) and logged at most once a minute, never audited and never naming an address; the link itself is checked from the laptop before the show, once cloudflared says it is registered (the round trip out to Cloudflare and back, five tries), and a check is of one tunnel, its end always said. The link runs until an end: the end of the show day (06:00, an hour or more away) when turned on, or the time of day Tunnel until… names, kept in the settings until Turn off, and said to every page in the laptop's words and time of day, never a page's own clock's; a start inside it turns the link on again and, once cloudflared gives the address, says it is new (a quick tunnel's is at every start), or says it could not, keeping the end for the next start; a start past it, or with an end no act could set, leaves it off, and a running link is turned off within a health window of its end, read against the wall clock, so a link no longer outlives its show because nobody closed a window. For a show with remote people a named Cloudflare Tunnel, run beside AGMessage, keeps one address. | `lib/guard.js` (`Places`, `limitKey`), `lib/peaks.js` (`Refusals`, `linkCheck`, `dayEnds`), `lib/tunnelend.js`, `server.js` (the connection's gate, `checkTunnel`, `tunnelAtStart`, `tunnelAtItsEnd`), `public/reconnect.js` |
| **Nothing heavy on the game loop.** Password hashing runs on libuv's pool, two at a time; checking the audit log reads off the loop and in slices, one check at a time; the halls board reads a hall's messages once per change, not once per watcher per tick; a hall's snapshot never reads back the snapshot it wrote: the one it replaces is copied to its backup unread when the store wrote it or loaded it whole (`snapWhole`), and read and parsed first only after a load that fell back to the backup, so a torn snapshot still never replaces a good one; synchronous file calls are counted per file and capped by a test; the event loop's true delay (its p99 less the sampler's own 10 ms resolution) and how busy it is (its utilisation) are measured every 5 s and shown. | `lib/accounts.js`, `lib/store.js` (`snapWhole`), `lib/resilience.js` (`writeFileAtomic`'s `knownWhole`, `readJsonWhole`), `test/resilience.test.js` (guard rails), `server.js` (health), `lib/peaks.js` |

## From medical device software: traceable, observed, fail-safe

| Practice | Where |
|---|---|
| **Attempts are not facts.** A command is sent → accepted → applied → observed. A send to Stagewatch reads its receipt and then the speaker's acknowledgement; a screen says "on screen" only when the screen confirms the numbered take it rendered. | `lib/nodes.js` (`readReceipt`), `lib/displays.js` (`shown`, `status`) |
| **Told until it is taken.** What an approved show-desk notice did is reported at least once and never runs twice: the desk refuses a second result (409), a busy key waits its Retry-After across the whole link, an unanswered post backs off, the waiting result is saved before its first post and outlives a restart, and every later post first reads the proposal back, so it reaches only the proposal that ran. | `lib/deskresults.js`, `server.js` (the desk loop), `lib/nodes.js` (`waitUntil`) |
| **An audit trail that shows tampering.** Every security-relevant action is appended, flushed to disk before it is acknowledged (or, when the disk will not take it, kept in the chain and written ahead of the next, or when the server stops), and chained with a key (HMAC-SHA256 under a key derived from the machine key) from a fixed first hash across rotated files, its records (the head, the log written last) kept outside the data folder; a check names the first broken file and line, reads one of four marks (✓ ◇ △ ✕, each a shape), and what a key cannot show is said (`docs/ACCOUNTS.md`). Entries it cannot check are accepted only at the laptop, with the token typed, and the acceptance is an entry of its own. | `lib/audit.js`, `verify/auditrules.js` |
| **Fail closed.** An unknown verb, role (a join's included), right, destination or content kind is refused, never defaulted; a screen's connection is heard for nothing but its reports; one person's pages relay to each other only the settings a page applies, each read by its type; the admin's support view hears only the admin page that frames it; a high-risk command to another show system only ever goes to a person to approve; a hall's side room is joined by its key only by the admin and the accounts it is given (a guest the admin links into it may forward there), by a guest only with the room's own guest code while the admin has it switched on (a side room's is off until then), never by its key or an account's halls, every hall's included; a guest code switched off, a code renewed since, a key and a code no room has are one answer to a lookup and a join, the renewed code admitting only a person already seated there; is never taken for a hall (a hall's screens, Stagewatch, show network and Set up refuse its key in their own words), and sends nothing to a Stagewatch and raises no help request, each refused with words rather than sent where it would not be followed; a room whose files another program holds as it is removed is said, its uploads kept for it when it would load again; a room or hall removed is taken out of every account that named it (one that comes back at the next start, its files held by another program, stays with them), and no new hall or room is made under a key a room, an account or a node's link still names, so a key made again later is never open to them; a setting of a room that its verb does not change is refused, never ignored; a Patterns or PlayMap linked for a hall that has been closed proposes to no show desk, never to the default Stagewatch's. | `lib/rbac.js`, `lib/store.js` (`get`, `room`, `byCode`, `byRetired`, `codeOn`), `lib/accounts.js` (`prune`), `lib/stagelines.js`, `lib/peerlinks.js`, `lib/handlers/rooms.js`, `server.js` (`serveDisplay`, `join`, `userStateOf`, `deskFor`), `public/app.js` (the support view's resync) |
| **What opens is what serves; a start that cannot run says why.** The browser opens on the copy that is serving, and only once it serves: the server opens `http://localhost:<PORT>` itself after it listens, asked by the .bat (`AGM_OPEN`), once per start of the window and never on a watchdog restart, so a page never opens on whatever else answers on the port. It opens only from the person's own session, the portable copy's: the installed node runs in Windows' session 0, where nothing it opened would be seen, so any channel but `portable` never opens. `explorer.exe` is run by its absolute path, never a bare name. A start that cannot run says why in its window: a file missing beside the .bat with its likely cause (started from inside the zip), exit codes the .bat reads as AGMessage's alone (2 missing, 3 cannot start, 0 stopped), and a port's holder, read from its own health at loopback with no token, which chooses only the words; a copy refused at the port leaves the show network before it reads. No test starts `explorer.exe` (each records the call instead): the browser coming up on a Windows desktop is the show laptop's to see. | `start-agmessage.bat`, `lib/startup.js`, `server.js` (after listen, `front`'s error) |
| **Only what it ships, only by its path.** A process is what it loads and what it starts. A `require()` that `app\node_modules` cannot answer makes Node walk every folder above it to the drive's root (`C:\node_modules`, which another account on the laptop may be able to make) and load what it finds there inside AGMessage, with its keys; so the server asks for nothing it does not ship: ws's native helpers are switched off before its first `require` (and by the watchdog), and `supports-color`, which `debug` looks for, ships with it. A program is started by its absolute path, never a bare name, which Windows looks for in the current folder and on `PATH` first, an argument array or not: its own `bin\cloudflared.exe` (a copy without it has no internet link: Turn on is refused with why before anything runs or an end is kept), `explorer.exe` and `powershell.exe` under a `SystemRoot` named from its drive, `reg.exe` in the installer's `{sys}`. The machine's own commands require Node's built-ins only. Each is a fence, not a habit: the server and its watchdog are started under a resolve hook with modules planted where the walk ends, what the run does not reach is read from the source (every ask of the shipped scripts, followed through each file it reaches), and every call in `app` that starts a program is read with ESLint's parser, however `child_process` is reached, and held to a register of where its full path is made (`docs/ANALYSIS.md` §3.7). | `server.js` (before its first `require`, `CLOUDFLARED`, `noCloudflared`), `supervise.js` (its child's environment, `AGM_CHILD` by `isFullPath`), `lib/startup.js` (`cloudflaredFile`, `noCloudflaredWords`, `isFullPath`), `app/package.json` (`supports-color`), `test/loads.test.js`, `test/resolve-preload.js` |
| **Written only once held; never made over what could not be read.** A copy reads every store first and writes nothing — no folder, key, certificate, secret or setting, in its data folder or its key folder — until it holds its data folder and its port; a stop or a crash before then saves nothing, since another copy may own those files. A secret is made only where there is none (the file not there, ENOENT): a machine key, server secret, certificate or context token that cannot be read or does not open is never replaced; the portable copy goes on without it and says so in its window (its own secret this run, HTTPS off, context reads refused with words), and the installed node does not run without it (code 3, before anything is made). Settings that cannot be read are never saved over, nor taken from their `.bak`: a setting changed that run is refused with why, never answered as done. A folder that cannot be made or read, or a channel AGMessage does not know, ends the start with code 3 and words that name it, never a crash loop; the installed node's port or folder held ends it with 75, which its watchdog tries again on its ladder and never counts as a crash. Once it listens, an error on the port (out of file handles) loses that connection, never the copy. | `server.js` (`firstWrites`, `taskKeysProblem`, `contextTokenProblem`, the port's error), `lib/startup.js` (`channelOf`), `lib/resilience.js` (`publishOnce`, `readText`, `EXIT.HELD`, the watchdog's policy), `lib/guard.js` (`readSecret`), `lib/tls.js` (`readCertificate`), `lib/secretbox.js` (`deferMaking`), `supervise.js`, `test/startrules.test.js` |
| **The token is said only where a person sits.** The watchdog makes the laptop's admin token and says it in the banner's Token line on a console only, once its server serves: never into output that is kept (a redirect, a log, a task's capture), where the line says where the token is instead, and a server under its watchdog never prints it (a server run alone still does). The installed node takes no secret from its environment (a task's definition is read by every account allowed to read the task) and writes its token into a token folder of its own, read by its admin and the accounts it gives `token`, only once its server holds its folder and port, so a copy that does not serve never writes over it. The first admin account is made only with the token, typed at the laptop or by the token's sign-in made by this run, never from loopback alone: the typed token judged first, a wrong one counted toward the token's lockout and written down. | `supervise.js` (`sayToken`), `lib/startup.js` (`taskTokenProblem`, `tokenLine`), `server.js` (`sayToken`, `typedTokenProblem`), `lib/http-accounts.js` (`/api/setup`), `launch.js` (`token`), `test/admintoken.test.js` |
| **Asked before it is stopped; proved before it is asked.** How live the server is, is one line of counts (a message or other input from a page, a take changed and a help request in the last 10 minutes, kept across a restart by the halls and the screens that hold them, a countdown running; seats and screens open and quiet beside them), never a name, code, token or path: activity is busy, presence is not, and a server that has not answered whole within 5 s reads busy. A busy server is stopped only with a reason a person typed, which is written. This PC's machine asks at loopback with a proof of the token, over a nonce the server issued for one request within 30 s, the method, the path and the body, and the token never crosses the socket: the machine first takes the server's own proof, over its nonce and the machine's fresh challenge, and asks nothing of a program that cannot give it. No browser is answered there, and no token under 16 characters, which a hello would let any program on the PC guess at offline. The data folder's pipe answers the line as a read to anyone, so what is read there chooses words and nothing else. | `lib/busy.js`, `lib/machinewire.js`, `server.js` (`busyNow`, `/api/machine/*`, the folder's hold), `test/busy.test.js` |
| **What the console says reaches the admin page.** A node with no window keeps what a window would show: the watchdog tees its server's output, line by line, to its console and to `data/logs/server.log`, bounded (two files of 2 MB, measured at some ten days of a held port) and never with the token (searched for by value, before a long line is cut), and its line for a start the server refused carries the server's own words, handed to a restart and, for the installed node, recorded for whichever start comes next. The admin page's answer carries the LAN addresses, the port and why HTTPS is off, as the banner says them, and "This laptop" says each fact with where it was read: what AGMessage knows, and what Windows says through one `powershell.exe` named by its absolute path, with a fixed script and an environment of named folders only, within 5 s, each part said as it is read so a read cut short keeps what it said, read by type, each part that could not be read said "unknown" with why, and every firewall rule judged — never a guess. A certificate due for renewal at a start with no network address serves on, never renewed without a person: the words say when New certificate renews it. | `supervise.js` (`tee`, `decide`, `record`), `lib/serverlog.js`, `lib/laptop.js`, `lib/tls.js` (`renewalWaits`, `networkAddresses`), `server.js` (`laptopFacts`, `laptopAnswer`, `readLaptop`, `httpsOff`, `renewalWords`, `beforeWords`), `test/laptop.test.js` |
| **Copies for inspection.** A record kept for inspection can be copied whole, accurate and in both human-readable and electronic form (21 CFR 11.10(b), [Cornell LII](https://www.law.cornell.edu/cfr/text/21/11.10)): the audit log is exported as its own files byte for byte with the laptop's verdict on them, signed (Ed25519, by a key derived from the machine key), and checked offline by a verifier that reads the lines and draws them as a table (`--list`, the page) — never by trusting the copy, which is untrusted input to it. The export is itself an audit row, and a copy that does not arrive whole is said as one. | `lib/auditexport.js`, `lib/zip.js`, `verify/` |
| **Kept across events.** Record changes shall not obscure previously recorded information, and records stay ready to retrieve throughout their retention (21 CFR 11.10(e) and (c), [Cornell LII](https://www.law.cornell.edu/cfr/text/21/11.10)): the audit log is one chain from event to event. Each event archived writes an archive point as the first line of a file of its own; the admin may split there, which moves whole files into a signed archive and never deletes or rewrites a line, pins it in a keyed entry before anything moves, and is refused while anything before the point is open or broken. The check then starts at the point and names every archive back to entry 1, its mark the worst of the live log's and each archive's, so a split never makes the log read better than it did; every archive is checkable on its own and inside every export. | `lib/auditarchive.js`, `lib/audit.js` (`point()`, the walk from a point), `verify/` |
| **Modules, fenced.** One composition root, `server.js`, builds every store, lane and link, and it alone requires the HTTP domain and the handler modules; a pure core requires only itself and reaches no disk, network or process; nothing requires `server.js`, and no file leads back to itself. Each is read from the source by a test that fails the build, and the lanes from health after boot, by the object. | `test/modules.test.js`, `test/helpers.js` (`handlerFiles()`), `lib/store.js` (`get` and `has` a hall, `room` and `allRooms` any room), `server.js` (`saveLanes()`, health's `saves.built` and `saves.named`; `conn`, `ctx`), `lib/resilience.js` (`WriteLane.built`), `lib/gate.js`, `lib/handlers/` |
| **Every hazard has a test.** Escalation, revocation under a live socket, tokens in files and logs, same-numbered acknowledgements and proposals from two Stagewatches or one restarted, a refused grammar, a show desk's answer AGMessage cannot read (an `ok` that is not a boolean, a state it does not know), a tampered audit line — each is a test that fails the build. | `app/test/*.test.js` |
| **The software of unknown provenance is listed.** Every release carries a CycloneDX bill of materials, the zip's SHA-256 and a build-provenance attestation; dependencies are audited with registry signatures weekly. | `.github/workflows/ci.yml`, `security.yml` |
| **Every build is identified, and "newer" is one rule.** One version scheme; the build a laptop runs is on its health page, its admin page and its hello. Newer is MAJOR.MINOR.BUILD, PlayMap's rule, and a release is published only above every one before it, so the orders agree among releases. | **Measured, then governed; and kept.** Nothing claimed that was not observed applies to speed too: no limit or governor lands without a reading that calls for it. ## Security in one list

Sealed secrets at rest (AES-256-GCM, a machine key outside the app folder) · scrypt passwords · hashed session tokens in
`HttpOnly`/`SameSite=Strict`/`Secure` cookies · an `Origin` check on every state change · a strict Content-Security-Policy
with no inline script · uploads allow-listed and checked by content, served so they cannot run script · HTML built only
from escaped parts (a lint rule) · names stripped of control and bidirectional characters · pinned certificates
between show systems, keys in headers and never in URLs · capability links for screens · CodeQL, a dependency audit and
a secret scan on every change. Details: `SECURITY.md`, `docs/ACCOUNTS.md`, `docs/DISPLAYS.md`, `docs/ANALYSIS.md`.
