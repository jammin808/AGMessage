# How AGMessage is built — speed, security and reliability

AGMessage runs a live event: a dropped message, a wrong screen or a leaked link happens in front of a room. It borrows
from two fields that live with that: **games** (many clients, unreliable networks, an authoritative server that must
never stall) and **medical device software** (every action traceable, every hazard tested, nothing claimed that was
not observed). This page says which practice is used where, so a change can keep it.

## From games: an authoritative server on an unreliable network

| Practice | Where |
|---|---|
| **Sequence numbers and deltas.** Every change to a room is an operation with a per-room number; a phone that drops off the Wi-Fi resumes with just what it missed, or a full snapshot when the gap is too old. One op table names the event each change is sent under, and the hall page applies a change it missed and one it hears live through the same row of its own table, so the two cannot draw it differently (Zulip applies one event stream to a fetched state and to live updates alike, [Zulip's events system](https://zulip.readthedocs.io/en/latest/subsystems/events-system.html)); a change the table cannot send is refused before it takes a number, so no page is left with a gap. | `lib/store.js` (`opsSince`, the ring), `lib/ops.js` (`UPD_EVENTS`, `applier`), `public/app.js` (`bump`, `rejoin`, `UPD_EVENTS`, `applyOp`) |
| **The server is the authority.** Identities are issued and signed by the server; a client never names itself, its role or its rights. Accounts' rights are read at connect and re-read when they change, and a browser signed in to an account joins as that account, never as a code guest. | `lib/guard.js` (identities), `lib/rbac.js`, `server.js` (`accountChanged`, `join`) |
| **Latest wins for state, never a backlog.** The halls board is pushed at most every 300 ms with the newest state; Stagewatch frames replace each other; a slow phone gets the newest board. | `server.js` (the board tick), `lib/nodes.js` (`_set`) |
| **Liveness from silence.** A link is stale after 6 s without a frame and redialled after 12 s with jittered backoff; a screen's countdown dims to `--:--` rather than show a confident stale time. | `lib/nodes.js`, `public/display.js` |
| **Rate limits and lockouts per client.** Token buckets for messages, chatter, uploads, AI and screen reports — uploads per connection and per address, so joining again or opening more sockets refills nothing; lockouts for guessing codes, tokens and passwords. | `lib/guard.js` (`Bucket`, `Lockout`), `server.js` (`/api/upload`) |
| **Nothing heavy on the game loop.** Password hashing runs on libuv's pool, two at a time; checking the audit log reads off the loop and in slices, one check at a time; the halls board reads a hall's messages once per change, not once per watcher per tick; synchronous file calls are counted per file and capped by a test; the event loop's true delay (its p99 less the sampler's own 10 ms resolution) and how busy it is (its utilisation) are measured every 5 s and shown. | `lib/accounts.js`, `test/resilience.test.js` (guard rails), `server.js` (health), `lib/peaks.js` |

## From medical device software: traceable, observed, fail-safe

| Practice | Where |
|---|---|
| **Attempts are not facts.** A command is sent → accepted → applied → observed. A send to Stagewatch reads its receipt and then the speaker's acknowledgement; a screen says "on screen" only when the screen confirms the numbered take it rendered. | `lib/nodes.js` (`readReceipt`), `lib/displays.js` (`shown`, `status`) |
| **Told until it is taken.** What an approved show-desk notice did is reported at least once and never runs twice: the desk refuses a second result (409), a busy key waits its Retry-After across the whole link, an unanswered post backs off, the waiting result is saved before its first post and outlives a restart, and every later post first reads the proposal back, so it reaches only the proposal that ran. | `lib/deskresults.js`, `server.js` (the desk loop), `lib/nodes.js` (`waitUntil`) |
| **An audit trail that shows tampering.** Every security-relevant action is appended, flushed to disk before it is acknowledged (or, when the disk will not take it, kept in the chain and written ahead of the next, or when the server stops), and chained with a key (HMAC-SHA256 under a key derived from the machine key) from a fixed first hash across rotated files, its records (the head, the log written last) kept outside the data folder; a check names the first broken file and line, reads one of four marks (✓ ◇ △ ✕, each a shape), and what a key cannot show is said (`docs/ACCOUNTS.md`). Entries it cannot check are accepted only at the laptop, with the token typed, and the acceptance is an entry of its own. | `lib/audit.js`, `verify/auditrules.js` |
| **Fail closed.** An unknown verb, role (a join's included), right, destination or content kind is refused, never defaulted; a screen's connection is heard for nothing but its reports; one person's pages relay to each other only the settings a page applies, each read by its type; the admin's support view hears only the admin page that frames it; a high-risk command to another show system only ever goes to a person to approve. | `lib/rbac.js`, `lib/stagelines.js`, `lib/peerlinks.js`, `server.js` (`serveDisplay`, `join`, `userStateOf`), `public/app.js` (the support view's resync) |
| **What opens is what serves; a start that cannot run says why.** The browser opens on the copy that is serving, and only once it serves: the server opens `http://localhost:<PORT>` itself after it listens, asked by the .bat (`AGM_OPEN`), once per start of the window and never on a watchdog restart, so a page never opens on whatever else answers on the port. It opens only from the person's own session, the portable copy's: the installed node runs in Windows' session 0, where nothing it opened would be seen, so any channel but `portable` never opens. `explorer.exe` is run by its absolute path, never a bare name. A start that cannot run says why in its window: a file missing beside the .bat with its likely cause (started from inside the zip), exit codes the .bat reads as AGMessage's alone (2 missing, 3 cannot start, 0 stopped), and a port's holder, read from its own health at loopback with no token, which chooses only the words; a copy refused at the port leaves the show network before it reads. No test starts `explorer.exe` (each records the call instead): the browser coming up on a Windows desktop is the show laptop's to see. | `start-agmessage.bat`, `lib/startup.js`, `server.js` (after listen, `front`'s error) |
| **Copies for inspection.** A record kept for inspection can be copied whole, accurate and in both human-readable and electronic form (21 CFR 11.10(b), [Cornell LII](https://www.law.cornell.edu/cfr/text/21/11.10)): the audit log is exported as its own files byte for byte with the laptop's verdict on them, signed (Ed25519, by a key derived from the machine key), and checked offline by a verifier that reads the lines and draws them as a table (`--list`, the page) — never by trusting the copy, which is untrusted input to it. The export is itself an audit row, and a copy that does not arrive whole is said as one. | `lib/auditexport.js`, `lib/zip.js`, `verify/` |
| **Kept across events.** Record changes shall not obscure previously recorded information, and records stay ready to retrieve throughout their retention (21 CFR 11.10(e) and (c), [Cornell LII](https://www.law.cornell.edu/cfr/text/21/11.10)): the audit log is one chain from event to event. Each event archived writes an archive point as the first line of a file of its own; the admin may split there, which moves whole files into a signed archive and never deletes or rewrites a line, pins it in a keyed entry before anything moves, and is refused while anything before the point is open or broken. The check then starts at the point and names every archive back to entry 1, its mark the worst of the live log's and each archive's, so a split never makes the log read better than it did; every archive is checkable on its own and inside every export. | `lib/auditarchive.js`, `lib/audit.js` (`point()`, the walk from a point), `verify/` |
| **Modules, fenced.** One composition root, `server.js`, builds every store, lane and link, and it alone requires the HTTP domain and the handler modules; a pure core requires only itself and reaches no disk, network or process; nothing requires `server.js`, and no file leads back to itself. Every event a page sends is a verb the server registers, every verb is sent by a page, and every event the server sends is heard by one, so no verb is kept that nothing uses, and no verb is registered where or how the input fuzz does not read it; the hall page's op table is the server's, field by field, and every change to a message names only the table's fields; every lane the server makes is one a stop or a crash flushes. Each is read from the source by a test that fails the build, and the lanes from health after boot, by the object. | `test/modules.test.js`, `test/helpers.js` (`handlerFiles()`), `server.js` (`saveLanes()`, health's `saves.built` and `saves.named`), `lib/resilience.js` (`WriteLane.built`) |
| **Every hazard has a test.** Escalation, revocation under a live socket, tokens in files and logs, same-numbered acknowledgements and proposals from two Stagewatches or one restarted, a refused grammar, a show desk's answer AGMessage cannot read (an `ok` that is not a boolean, a state it does not know), a tampered audit line — each is a test that fails the build. | `app/test/*.test.js` |
| **The software of unknown provenance is listed.** Every release carries a CycloneDX bill of materials, the zip's SHA-256 and a build-provenance attestation; dependencies are audited with registry signatures weekly. | `.github/workflows/ci.yml`, `security.yml` |
| **Every build is identified.** One version scheme; the build a laptop runs is on its health page, its admin page and its hello. | `lib/version.js`, `tools/stamp-build.js` |
| **Measured, then governed; and kept.** Nothing claimed that was not observed applies to speed too: no limit or governor lands without a reading that calls for it. The readings are taken in place on the show laptop — the loop's delay and how busy it is per 5 s window, the sockets per address and through the tunnel, the largest hall, the most joins one hall took in 5 s, each snapshot write and each audit append (open, write, fsync, close) timed where it runs — and each show day (06:00 to 06:00 by the laptop's clock, so an evening past midnight is one day) keeps the highest of each, the last 14 show days, in `peaks.json` through a write lane at the end of each 5 s window in which one rose, and at once at a stop or a caught crash: a restart loses none of the day they are for, and a hang the watchdog ends or a power cut at most that window. Timing never reaches what it times: a fault in the bookkeeping leaves the snapshot or the audit entry on disk. One look after a show is the reading; the table below says which it is waiting for. | `lib/peaks.js`, `server.js` (health), `lib/store.js` (`onCompact`), `lib/audit.js` (`onPut`) |
| **Recover, don't stop.** A watchdog restarts a crashed or hung server with backoff; saves are atomic with a backup of the last whole copy (a save the disk cuts short is a failure, never a short file renamed over a whole one), and a save that fails is kept, retried until it lands and named on the admin page's health; sessions, rooms, screens, settings and the show desk's results not yet taken survive the restart. A stop — Ctrl+C, the console window closed, the watchdog's own — is asked of the server over IPC, so it saves first on Windows too, where a signal sent to a child process ends it unsaved; a server whose watchdog has gone saves and leaves (on Windows it is ended with the watchdog), so no orphan holds the folder. One server per data folder: a second copy (the same port or another) stops before it writes anything. Uploads pause while the disk is short of space, so the logs and saves always have room; files nobody posted, or that a reset or a deletion cleared, leave the disk. | `supervise.js`, `lib/resilience.js`, `lib/store.js`, `server.js` (boot, uploads) |

## Measured on the show laptop

What each reading of health's `peaks` (and the walks beside them) triggers, from the 0.6.0 plan (Part 5 §13.4). A row
says "not measured" until a show or a rehearsal on the show laptop fills it, with the day and the build: that is a
fact, not a block. Only a recorded number goes here. A day in `peaks` is a show day: from 06:00 to 06:00 by the show
laptop's clock, named by the date it starts (health's `showDay` names the one it is in now).

| # | Reading | Where it comes from | Threshold | Then | Measured |
|---|---|---|---|---|---|
| 0 | The fan-out bench, with a fixed count (on a VM), and its tunnel row | the bench, recorded to its results file | — | sets the numbers the papers may quote | not measured |
| 1 | The largest hall's messages on a show day | `peaks.hallMessages` | ≥ 5,000 | "Show earlier" and a room switch timed again on an iPad and a phone; the first open's 200 kept or changed with the number | not measured |
| 2 | The most sockets from one venue address | `peaks.socketsPerAddress` (the most from any one address, until the tunnel's are counted apart) | > 30 (the connection bucket's burst) | the burst becomes the reading plus a quarter, with a test that that many pages from one address come back after a restart | not measured |
| 3 | An fsync on the laptop's disk | `peaks.auditPutMs` (p99 and max) | p99 ≤ 2 ms and max ≤ 100 ms | group commit: an acknowledged message is on disk, and the papers say so | not measured |
| 4 | The snapshot stall at the largest hall's size | `peaks.compactMs` (with its hall's messages) | > 50 ms | snapshots move to a quiet moment | not measured |
| 5 | Board pages hidden while a take is current | `peaks.pageHiddenMs` (from the pushed screens' unit) | over 30 s | that device's wake row walked again; the hour-before-doors card gains the screen setting | not measured |
| 6 | The loop on a show day | `peaks.loopMs` (the worst 5 s window's p99), `peaks.elu` | p99 over 50 ms, or busy over 0.5 | a CPU profile of the next rehearsal before any change; nothing governed on this alone | not measured |
| 7 | The internet link, before doors and after the show | the link's check and one phone on mobile data; after: `peaks.tunnelSockets`, `peaks.hallKb` | before: the check fails, its max over 1 s, or the phone's open over 5 s; after: any refusal, or 120 of 150 places | the remote people told before doors; the named tunnel taken up | not measured |
| 8 | A doors-open join storm | `peaks.joinBurst` (the most in any 5 s, read at each join in quarter-second slots, so the 5 s tick never cuts a storm in two) | ≥ 50 joins in one hall in 5 s | presence lines coalesce into one per room per 2 s | not measured |
| 9 | The glance test (a walk) | a Board member under the stage lights, on each kind of Board device | fails on any | the simple view's sizes raised | not measured |

## Security in one list

Sealed secrets at rest (AES-256-GCM, a machine key outside the app folder) · scrypt passwords · hashed session tokens in
`HttpOnly`/`SameSite=Strict`/`Secure` cookies · an `Origin` check on every state change · a strict Content-Security-Policy
with no inline script · uploads allow-listed and checked by content, served so they cannot run script · HTML built only
from escaped parts (a lint rule) · names stripped of control and bidirectional characters · pinned certificates
between show systems, keys in headers and never in URLs · capability links for screens · CodeQL, a dependency audit and
a secret scan on every change. Details: `SECURITY.md`, `docs/ACCOUNTS.md`, `docs/DISPLAYS.md`, `docs/ANALYSIS.md`.
