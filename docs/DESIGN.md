# How AGMessage is built — speed, security and reliability

AGMessage runs a live event: a dropped message, a wrong screen or a leaked link happens in front of a room. It borrows
from two fields that live with that: **games** (many clients, unreliable networks, an authoritative server that must
never stall) and **medical device software** (every action traceable, every hazard tested, nothing claimed that was
not observed). This page says which practice is used where, so a change can keep it.

## From games: an authoritative server on an unreliable network

| **Sequence numbers and deltas.** Every change to a room is an operation with a per-room number, a hall's Main room's and each side room's its own, and a page holds one room (a move to another room of its hall, by its switcher, is a page of its own, so each stream stays one room's); a phone that drops off the Wi-Fi resumes with just what it missed, or opens again when the gap is too old. A first open is bounded, as a messenger's is: the room's newest 200 messages and, from before them, only what a page keeps in view (every pinned message, help not resolved, every question not answered; these and the index grow with the day, the run does not) and an index of the room's files, the newest 60 drawn at once and the rest as the page is idle; earlier messages come 200 at a time when asked for (Show earlier, or a reply's Show it), and a message pinned since by its id, each the room's record as it stands, so a change made to it meanwhile is in it, and a reply whose quoted message has gone says so, so no page reads back for it. | **Back by itself.** A page is never left dead: a connection the server refuses for its rate carries when to try again (`retryMs`: never before the network's bucket holds its next token, at least 1 s, plus up to 2 s chosen at random so the pages behind one network do not come back in the same instant; 30 to 40 s for a place through the tunnel) and what it refused (`why`, in words that name the wait), and the page tries then, saying so in those words, while a refusal no wait lifts (HTTPS required) says `retry: false` and is never tried; after a drop Socket.IO tries again from 0.5 s, doubling to 2 s, each ±50 %, and a page shown again or back online that is not connected starts afresh at once instead of waiting out its backoff (Socket.IO's own `connect()` does nothing while it waits). A page its tab leaves closes its socket (`pagehide`), so the server hears it go then: a browser keeps a page it may show again (its back-forward cache) frozen with its connection open, which would leave the person seated in the room they left until its pings went unanswered; shown again from that cache, it connects again and joins as after a drop ([web.dev on the back/forward cache](https://web.dev/articles/bfcache): close open connections in `pagehide`, reopen them in `pageshow`). A page down 2 s says so in words, never by colour alone; a screen the audience sees tries again in silence. A restart announces nobody: in its first 30 s a page naming a change its hall holds is one coming back, and the restart's own line says what happened. The watchdog's first restart waits 0.5 s, a step the Windows job's 20 kills in a row hold. Back on a new build, a page comes back as that build without cutting what a person is doing: each page names the build that served it as it connects, every answer it reads its server's build from carries the server's, and one on another build reloads itself at its own quiet moment, only while it is connected, so a reload never lands on a server it cannot reach (a hall page with nothing written and unsent and no act waiting on its answer, no dialog and no document on its stage, untouched for 5 s; the halls board likewise; a screen between takes, so no take on the air is cut; the admin page when its admin agrees), by itself once per build in a tab, onto scripts and styles the browser checks with the server at every load (no-cache, a 304 while unchanged) rather than the old build's from its cache. 0.5.1's pages, which name no build, are told to reload (`account:changed`) only once none of 0.5.1's files can still be fresh in a browser, 5 minutes after the start, so their reload brings the new build whole; a 0.5.1 screen cannot be, and "This laptop" names it. | `public/reconnect.js` (`AGM.reconnect`, `AGM.reconnect.build`), `server.js` (the connection's refusal, `join`'s `returning`, `/build.js`, `tellOld`, `pagesElsewhere`), `lib/guard.js` (`Bucket.waitMs`), `lib/resilience.js` (`SupervisorPolicy`) |
| **The server is the authority.** Identities are issued and signed by the server; a client never names itself, its role or its rights. Accounts' rights are read at connect and re-read when they change, and a browser signed in to an account joins as that account, never as a code guest. A seat has a limit, read before any right, the admin's included: On stage holds reading and writing messages and nothing else (no file, no question, nothing into another room, no screen, set-up, show network or draft, and no answer to someone else's help request: only its own Resolved), refused on the server whatever the page sends; the seat is the socket's, set at the join and moved only by the admin, and an upload token is checked against it again at use and ended in the tick the admin moves the page to a seat that shares no file. | **Latest wins for state, never a backlog.** Eight frames of state go through one primitive, `Latest`: a change after a quiet window is sent on the next turn, the changes inside a window fold into one frame at its end, each with its newest state, and none is dropped — nothing is volatile, so the last change always arrives, and a page that stops reading is let go by the heartbeat. They are the halls board (300 ms), a hall's screens console (150 ms), its people list (100 ms), its seen receipts (1 s, one frame per hall holding every receipt that moved), its rooms (300 ms: each page in any of them told the hall's name and the rooms its switcher moves between, when one is made, renamed or removed or the hall renamed), the rooms a room's pages may send into (300 ms: each page in the room told to ask again, `sendsChanged`, which names nothing, when a list that names the room changes or a room it sends into, or that room's hall, is renamed), what a hall's people's pages are shown (150 ms: each console of the hall told to read it again, `pages:changed`, which names nothing, when a take is pushed, a page reports on one, a page comes or goes, or a seat moves), and a room's news (500 ms: each page that may move into the room from another room of its hall, its switcher's, told the room's news as it stands when the frame goes, its newest message's and its newest priority one's change numbers, and whether a priority message came, `rooms:activity`, which carries no words, sender or people, when a message comes, is removed or the room is cleared; the merge, `lib/ops.js`'s, keeps any 🔥, so a burst inside one window is two frames and a priority message among it is never folded away), and health's `latest` says what each saved; a timer of its own in a handler file is counted by a test, each with its reason. A frame only reads the state, so one that faults while it is built is refused and counted in health's `handlerFaults`, as a handler's throw is, and the other halls' and watchers' frames still go. Outside it: `nodes:changed`, sent when a linked node's light changes or the admin links, unlinks or confirms one, and for the nodes heard on the network at most every 500 ms by their own coalescer; and Stagewatch frames, which replace each other, each sent when its view changes. | **Fewer frames, not smaller ones.** Frames are not deflated: a broadcast is framed once and that frame written to every socket of it, where per-message deflate compressed it again for each (Socket.IO ships it off for its cost in CPU and memory, [server options](https://socket.io/docs/v4/server-options/)); HTTP long-polling keeps HTTP compression. A join storm and a burst of receipts are one frame per window, not one per event to every page. Undeflated, a first open would grow with a hall's whole day, which a phone through the internet link on mobile data feels: so it carries the newest 200 (owner answer 33) and what a page keeps in view from before them, and the rest only when asked for. | `server.js` (`perMessageDeflate`, `frames`), `lib/store.js` (`firstOpen`) |
| **Liveness from silence.** A link is stale after 6 s without a frame and redialled after 12 s with jittered backoff; a screen's countdown dims to `--:--` rather than show a confident stale time. | `lib/nodes.js`, `public/display.js` |
| **Rate limits and lockouts per client.** Token buckets for messages, chatter, uploads, AI and screen reports — uploads per connection and per network, so joining again, opening more sockets or taking the next address refills nothing; lockouts for guessing codes, tokens and passwords. A bound per address counts a network (`limitKey`): through the tunnel an IPv6 address by its /64, which a mobile network gives each phone and within which the phone changes address (RFC 6459 §5.2, RFC 8981), so one phone never steps out of a bound by its next address; a venue address whole. The one bound that keeps the full address is the sign-in's own allowance and lock per address, because through the tunnel its lock per name holds for the whole tunnel. The buckets of connections, room lookups and uploads are bounded at 5,000 networks and never reset: the fullest go first, so a flood of new addresses hands no drained network its burst back. | `lib/guard.js` (`Bucket`, `Buckets`, `Lockout`, `limitKey`), `server.js` (`/api/upload`, the connection's gate, `join`, `/api/rooms/:code`, `/api/context`) |
| **The internet link.** Remote phones come through a Cloudflare Quick Tunnel, which takes 200 requests in flight and answers the rest 429 where AGMessage never hears of them; an open page holds one for as long as it lives. So the tunnel has 150 places (50 kept for page loads, files and uploads), one network half of them at most, and AGMessage refuses past them itself, in words that say what was refused and when the page tries again, which it does by itself. The number rests on the cautious reading that an open WebSocket counts against Cloudflare's 200, until reading 0's tunnel row (below) says; if it does not, the places become the largest fan-out reading 0 records with delivery p99 under 50 ms. The venue never waits for the tunnel. A place is for a page in a room: a socket that has not joined one within 20 s, and carries no account, admin token or screen link, gives its place back. Every refusal is counted per show day by kind in health and in the day's peaks (so a restart carries on from them) and logged at most once a minute, never audited and never naming an address; the link itself is checked from the laptop before the show, once cloudflared says it is registered (the round trip out to Cloudflare and back, five tries), and a check is of one tunnel, its end always said. The link runs until an end: the end of the show day (06:00, an hour or more away) when turned on, or the time of day Tunnel until… names, kept in the settings until Turn off, and said to every page in the laptop's words and time of day, never a page's own clock's; a start inside it turns the link on again and, once cloudflared gives the address, says it is new (a quick tunnel's is at every start), or says it could not, keeping the end for the next start; a start past it, or with an end no act could set, leaves it off, and a running link is turned off within a health window of its end, read against the wall clock, so a link no longer outlives its show because nobody closed a window. For a show with remote people a named Cloudflare Tunnel, run beside AGMessage, keeps one address. | `lib/guard.js` (`Places`, `limitKey`), `lib/peaks.js` (`Refusals`, `linkCheck`, `dayEnds`), `lib/tunnelend.js`, `server.js` (the connection's gate, `checkTunnel`, `tunnelAtStart`, `tunnelAtItsEnd`), `public/reconnect.js` |
| **Nothing heavy on the game loop.** Password hashing runs on libuv's pool, two at a time; checking the audit log reads off the loop and in slices, one check at a time; the halls board reads a hall's messages once per change, not once per watcher per tick; a hall's snapshot never reads back the snapshot it wrote: the one it replaces is copied to its backup unread when the store wrote it or loaded it whole (`snapWhole`), and read and parsed first only after a load that fell back to the backup, so a torn snapshot still never replaces a good one; synchronous file calls are counted per file and capped by a test; the event loop's true delay (its p99 less the sampler's own 10 ms resolution) and how busy it is (its utilisation) are measured every 5 s and shown. | `lib/accounts.js`, `lib/store.js` (`snapWhole`), `lib/resilience.js` (`writeFileAtomic`'s `knownWhole`, `readJsonWhole`), `test/resilience.test.js` (guard rails), `server.js` (health), `lib/peaks.js` |

## From medical device software: traceable, observed, fail-safe

| Practice | Where |
|---|---|
| **Attempts are not facts.** A command is sent → accepted → applied → observed. A send to Stagewatch reads its receipt and then the speaker's acknowledgement; a screen says "on screen" only when the screen confirms the numbered take it rendered; a take on people's pages is "◷ Sending" until each page that holds it says what it did with it, and ✓ only once every one said it showed that take (a web page, whose frame cannot be seen into, reads ◇ opened once it loads, never ✓) (a page's report of an older take, or from the admin's view of someone, counts for nothing); a page says it showed a take only while it is in view, and only once it has drawn it (the renderer answers what it drew, and the page alone says it to the server). Where a Board member's message also went is said on it, for every reader of the room, from what its targets confirmed and never from the send: "⏱ Lectern: sending" until the screen confirms its numbered take ("⏱ On Lectern ✓", or △ when it could not, "Replaced on Lectern at 14:12" once it moved on), and "👥 Shown to 5 of 6 On stage" counting, of the people On stage it went to, only those a page of whose said it showed the card in their side bar (by person, never by page: a page that comes back is its person, and someone seated since is nobody it went to); the server follows each such message and updates its words once a second at most. | `lib/nodes.js` (`readReceipt`), `lib/displays.js` (`shown`, `status`), `lib/pages.js` (`report`, `status`), `lib/handlers/takes.js`, `public/pagelayer.mjs`, `public/app.js` (`Takes`, `Simple`) |

a guest code switched off, a code renewed since, a key and a code no room has are one answer to a lookup and a join, the renewed code admitting only a person already seated there; is never taken for a hall (a hall's screens, Stagewatch, show network and Set up refuse its key in their own words), and follows its hall: it sends only to its hall's Stagewatch, never the default, by the rights of the seat that sends (a side room's guest holds none), and its help request is shown whole only to those who may read the room, the hall's crew seeing it without its words; a room whose files another program holds as it is removed is said, its uploads kept for it when it would load again; a room or hall removed is taken out of every account that named it (one that comes back at the next start, its files held by another program, stays with them), and no new hall or room is made under a key a room, an account or a node's link still names, so a key made again later is never open to them; a setting of a room that its verb does not change is refused, never ignored; an account's list of halls, side rooms or On stage halls that is not a list of keys, a side room or On stage hall added to it that no room or hall has (a list of halls takes a key as given, as 0.5.1's did), and a chat view that is none of the three, is refused with words, never kept; a Patterns or PlayMap linked for a hall that has been closed proposes to no show desk, never to the default Stagewatch's; a file message names an upload made for its room by the person who posts it, or one a message of that room holds already, and any other upload's link (another room's, another person's, one only a screen holds, one made before a restart) is refused, never posted, and `buildMessage` builds no message of it whoever calls it; ## Security in one list

Sealed secrets at rest (AES-256-GCM, a machine key outside the app folder) · scrypt passwords · hashed session tokens in
`HttpOnly`/`SameSite=Strict`/`Secure` cookies · an `Origin` check on every state change · a strict Content-Security-Policy
with no inline script, and only the hall page may frame an https page: a web page shown to a person, in the one frame
a page makes, sandboxed for scripts alone (no forms, popups or navigation of the page around it), sent no referrer and no
feature, its address sealed at rest and named everywhere else by its host, never fetched by the server and never
AGMessage itself · uploads allow-listed and checked by content, an Office file's archive and a picture's size checked
before anyone opens them (and again at a file's first take on the stage), served so they cannot run script, `no-store`,
never as `attachment` and never to a navigation (Fetch Metadata), so a device keeps no copy and a `GET` never saves · a
file shown on people's pages only from a place the stage may show it from, a document never to an observer, drawn from
memory and let go with its take, a stage-only picture living while a take names it · a download a ticketed server act
(per seat, single use, 60 s, bound to its person, file and address) and a `GET` never one; an observer's page and a
Viewer account's never given a file's link, withheld at delivery; a file opening itself on nobody's panel, and moved to
another room only by a seat that may download it · files to transfer only (zip, media, OpenDocument, protected Office)
checked by their first bytes (a protected Office file by its compound file's directory) and never opened · HTML built only
from escaped parts (a lint rule, which refuses `srcdoc`, `setHTMLUnsafe`, `createContextualFragment` and a computed
`innerHTML` outright) · names stripped of control and bidirectional characters · pinned certificates
between show systems, keys in headers and never in URLs · capability links for screens · CodeQL, a dependency audit and
a secret scan on every change. Details: `SECURITY.md`, `docs/ACCOUNTS.md`, `docs/DISPLAYS.md`, `docs/ANALYSIS.md`.
