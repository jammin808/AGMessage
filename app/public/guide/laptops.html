The show laptop and crew laptops

The installer

Run AGMessage-Setup-<version>-unsigned.exe from the Windows account you run shows from, standard or administrator. Windows asks for an administrator's approval once. There is no folder page and no port page: AGMessage always goes in C:\Program Files\AGMessage, which only administrators may change, and on port 3023. Its pages, in order:

  1. Smart App Control, only while Windows is still evaluating the PC: the installer is unsigned. Where Smart App Control is on, Windows blocks it before it runs; turn it off in Windows Security → App & browser control → Smart App Control.
  2. AGMessage's admin on this PC (a first install): the Windows account AGMessage will belong to, the one that started the installer. When an administrator approved it, that administrator gets no AGMessage rights; if two accounts could be meant, it asks you to choose.
  3. Networks: one tick, Also on Public networks (hotels, airports, fresh venue Wi-Fi), unticked by default. See the firewall and networks.
  4. AGMessage is busy, only when people are using it (an upgrade): type why you stop it now, or cancel and install once it is quiet. The reason goes into the audit log.
  5. A portable AGMessage (a first install): Start with no halls, or Import a portable AGMessage folder: moving a portable folder in.
  6. The first admin account: make AGMessage's first admin account now, or leave it empty and make it later at the laptop, with the token.

It refuses an installer older than the build installed (uninstall first to go back), the same build again, and a second installer while one runs; each says Nothing was changed. For a quiet install from a command prompt it takes /VERYSILENT, /ADMIN=<account> (one person's account) and /PUBLICFIREWALL=1 or =0.

The Start menu

Start → AGMessage holds AGMessage's commands. Each opens a console window as the person who clicked it, never as an administrator, and waits for Enter before it closes; Open AGMessage closes by itself once it has opened the browser.

Open AGMessage
Opens http://localhost:3023 in your browser when AGMessage answers. Otherwise it says what it found: a portable copy holding the port, another program, or AGMessage is not serving on this PC.
Show the admin token
The token for Admin login on this PC. It changes at every start, so show it again after a restart or an upgrade.
Start AGMessage
Starts it and waits for it to answer, or says it is running already. If it does not answer within about half a minute it is left running, still starting: try again in a minute.
Stop AGMessage...
Saves, then stops. When people are using it, it says how busy it is and asks why; Enter alone leaves it running.
Upgrade AGMessage...
See upgrades and going back.
Go back to build N
Only after an upgrade, named for the build it replaced.
Who may run AGMessage...
Lists the laptop's admin and every right given, and takes one line to change them: next section.
AGMessage status
How AGMessage runs: its server task, the laptop's admin, the port, the last stop and the log's last line.

△ Watch for Close AGMessage's own consoles before an upgrade or an uninstall: an open one is named and the step refused. And if the watchdog that runs AGMessage itself crashes, Windows does not start it again: use Start AGMessage, or restart the PC. This laptop says so beside the build.

Who may run AGMessage on Windows

The laptop's admin is one Windows account, standard or administrator: by default, the account that ran the installer. It reads the admin token, starts, stops and upgrades AGMessage, and gives these rights to other people's Windows accounts. There are four rights: token (reads the admin token), start, stop and upgrade (which covers going back too). These are Windows rights only: they give nothing inside AGMessage.

  1. As the laptop's admin, open Start → AGMessage → Who may run AGMessage.... It lists who may do what.
  2. Type one line and press Enter:
    • Give LAPTOP\ben: start, stop gives rights.
    • Take back from LAPTOP\ben: stop (or all) takes them back, at once.
    • Hand over to LAPTOP\ben makes that account the laptop's admin; you type its name again to confirm, and you keep no right unless it gives one back.
  3. Enter alone closes it with Nothing was changed.

Rights go to one person's account; a group or a service is refused. Only the laptop's admin gives them, and an account given rights cannot pass them on. If the admin's Windows account is gone, an administrator runs Who may run AGMessage... as administrator and hands it over. Every right given, taken back or handed over, every start and stop, and every refusal is a row in the audit log.

Running the portable folder

  1. Extract the zip (right-click → Extract All), open the AGMessage folder and double-click start-agmessage.bat.
  2. Leave the black window open while the show runs. Its banner gives the Local: and LAN: addresses and, under Admin login, the Token:.
  3. To stop, press Ctrl+C in the window (it saves first), or close it.
  • If the server stops by itself, its watchdog starts it again: after half a second, then 4, 8, 15 and 30 seconds. After more than 6 crashes in 10 minutes it gives up, and the window says AGMessage did not start - the reason is above.
  • If a part of the copy is missing, the window names it: download the zip again and Extract All. An antivirus may be removing it.
  • Each new folder is a new node.exe to Windows Firewall, which asks again.
  • The folder's keys are kept in the Windows account's %LOCALAPPDATA%\AGMessage, not in the folder: start a copied folder from the same Windows account, or its accounts are held aside until the token adopts them.
  • Before handing the folder to anyone, run make-shareable-copy.bat. It makes a copy beside it with no halls, files, keys or settings, and checks it before it says Done.

Moving a portable folder in

On a first install, after its files and before AGMessage first starts, the installer offers Import a portable AGMessage folder. It copies the folder's halls, messages, files, accounts, screens and keys, checks what it copied, and only then retires the folder.

  1. Upgrade the portable folder to the installer's build, start it once and stop it with Ctrl+C.
  2. Run the installer from the Windows account that ran the folder: its keys are in that account's profile, and the import is offered only when that account is AGMessage's admin here.
  3. Choose Import a portable AGMessage folder, then the folder that holds start-agmessage.bat, then Next.

△ Watch for Once the check passes, the folder no longer starts, and the keys are removed from %LOCALAPPDATA%\AGMessage, which every portable folder of that Windows account shares. Once AGMessage has started, no portable folder can be brought in.

This laptop, on the admin page

💻 This laptop lists what AGMessage and Windows say about the laptop, each fact with where it was read; Refresh reads them again, and Copy LAN address copies an address for devices. Only an admin sees its acts.

  • Addresses: what devices open.
  • Network: Private, Public or Domain.
  • Firewall: whether a rule lets AGMessage in on that profile.
  • Sleep on mains and Lid closed on mains.
  • Kept awake and Sleeps.
  • Pages: each page and screen still on another build.
  • The server task, The laptop's admin and Rights given.
  • HTTPS, Screens, Stagewatch, Internet link, Data folder and Last stop.

Sleep, the lid and the power button

While a hall is live (a page open in it, a screen showing something, or its countdown running), AGMessage asks Windows to keep the laptop from idle sleep, and This laptop says Kept awake. The lid and the power button still follow the power plan.

  • Before doors, set "When I close the lid" to "Do nothing" on mains, in Windows' power settings.
  • On battery, a laptop with Modern Standby keeps the request 5 minutes at most: run the show on mains.
  • A sleep is told from a hang: the watchdog never counts the time asleep as a crash, and This laptop lists it under Sleeps.

The firewall and networks

The installer makes two Windows Firewall rules for AGMessage, each for the laptop's own subnet: the web port (TCP 3023) and discovery (UDP 9928). They cover Private and Domain networks, and Public only when the installer's tick Also on Public networks (hotels, airports, fresh venue Wi-Fi) was ticked.

△ Watch for Windows makes every new network Public. On fresh venue Wi-Fi, phones and laptops cannot reach an installed AGMessage until the network is made Private (Settings → Network & internet → the network → Private network) or the installer is run again with the Public tick. Devices on another subnet or VLAN of the venue network are not let in either way.

This laptop's Firewall row says, for each connected network, whether AGMessage is allowed there. A portable folder asks on its first start instead: choose Allow access, and on a Public network allow Public too, or make the network Private.

Logs

  • Installed: C:\ProgramData\AGMessage\logs\server.log, which the laptop's admin may read.
  • Portable: app\data\logs\server.log, beside what the black window shows.
  • Past 2 MB it becomes server.1.log, about 4 MB in all. It never holds the admin token.

Upgrades and going back

Upgrade between shows, never the night before one: upgrade, rehearse, then run the show on the build you rehearsed.

Installed

  1. Open Start → AGMessage → Upgrade AGMessage... (the laptop's admin, or an account given the upgrade right). It looks up AGMessage's newest release.
  2. Press Enter to install it, or type the full path of an installer you downloaded. It must be newer than this build, and its digest must match its release; a file that does not is refused: This file is not the release's. Do not run it.
  3. Close the console. The upgrade runs once it has: AGMessage saves and backs its data up, the new build is laid down, and AGMessage starts. If it does not answer, the earlier build and its data are laid back by themselves.

With no internet, the installer cannot be checked against its release: run it yourself, and Windows asks for an administrator. When people are using AGMessage, Upgrade asks why; Enter alone leaves it as it is.

Go back to build N (after an upgrade) asks you to type that build's number. AGMessage stops, its data is laid back as it was when the newer build was installed (what was written since is not kept, though the audit log is), and the older build is laid down from the installer kept on this PC.

Portable

  1. Stop the old copy with Ctrl+C in its window.
  2. Extract the new zip into a new folder.
  3. Copy app\data and app\uploads from the old folder into the new one, before its first start.
  4. Start the new folder from the same Windows account.

After an upgrade, open pages reload themselves onto the new build at a quiet moment; screens reload at their next take. Screens left open from 0.5 need one reload by hand.

Data, backups and uninstalling

  • An installed upgrade backs the data folder up first, into data\backups; the two newest are kept.
  • Uninstall from Windows' installed apps, where AGMessage is listed with its version and build. It asks Remove all AGMessage data from this PC?: No, the default, keeps every hall, account, file and key for a later install, which asks again whose AGMessage it is. Yes removes them, the keys last, and cannot be undone.
  • A busy AGMessage is uninstalled only with a reason typed at a command prompt (unins000.exe /FORCE="why").
  • A data folder copied to another laptop or Windows account keeps its accounts held aside until the token adopts them: accounts held aside.

Crew laptops

A crew laptop needs nothing installed: a browser on the venue network.

Reaching AGMessage

  • Open AGMessage's address: the portable window's LAN: line, or This laptop's Addresses (for example http://192.168.1.42:3023).
  • Off the venue network, the internet link's public address, while it is on.
  • Browsers from Chrome 84 and Safari 14.1 (iOS and iPadOS 14.5) up. An older one shows one line and opens nothing: This browser is too old for AGMessage. Update this device (iPadOS or iOS 14.5, or Chrome 84, or later), or use another.

Trusting the certificate

Open /tls on AGMessage's address, check the fingerprint against the admin page's 🔒 Encrypted connections, press Download the certificate and follow its steps: on Windows, Install Certificate → Local Machine → Trusted Root Certification Authorities; on a Mac, Keychain Access → Always Trust. Then open AGMessage with https://.

Signing in, or joining with a code

  • Crew with an account use the Sign in tab. A first sign-in with a one-time password asks them to choose their own: Choose your password.
  • Crew without one use Join with a code: the hall's code, their name, and the Backstage seat.
  • A browser signed in to an account does not join with a code; it offers Open your halls or Sign out.

The halls board and the hall page

  • Your halls lists each hall the account may see, with Needs help above it. Its header has Accounts and Admin where allowed, Password, the theme and Sign out.
  • Everything has a ⋯. A right-click, Shift+F10 and the menu key open the same list; Shift+right-click opens the browser's own menu. An act that cannot run now is greyed, with why.
  • On a message with the focus: R reply, E react, S Show the Board, F Send to, P pin, D download, Enter Preview.

When the connection drops

Pages come back by themselves. After 2 seconds down, the hall page says Reconnecting… what you write waits here until we're back.; what someone writes waits on the page, even through a reload, and is sent once when it is back, never twice. After an upgrade, a page reloads onto the new build at a quiet moment.
