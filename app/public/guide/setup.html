Installed or portable

AGMessage comes two ways, and both serve the same pages.

  • Installed, for your own show laptop: the installer (AGMessage-Setup-<version>-unsigned.exe) puts it in C:\Program Files\AGMessage and its data in C:\ProgramData\AGMessage. It starts with Windows, with nobody signed in, and has no window: you reach it from Start → AGMessage.
  • Portable, for a venue's laptop or any laptop that is not yours: a zip with its own runtime. Nothing is installed; it runs in a black window that stays open while the show runs.

Both answer on port 3023. Laptops says more about each, and how to move a portable folder into an installed AGMessage.

The first start

Portable

  1. Right-click the zip and choose Extract All. A copy started from inside the zip stops and says AGMessage was started from inside the zip.
  2. In the AGMessage folder, double-click start-agmessage.bat. A black window opens and says AGMessage is starting... Leave it open while the show runs.
  3. The first time a folder serves, Windows Firewall asks about node.exe: choose Allow access. On a standard Windows account this needs an administrator's password.
  4. The window shows the addresses: Local: for this laptop and LAN: for everyone else (for example http://192.168.1.42:3023), then the Admin login block with its Token: line. Your browser opens on this copy once it serves.
  5. Share the LAN: address with the crew and the Board. They open it in any browser on the venue network.

To stop, close the window or press Ctrl+C in it. Halls, messages and accounts are kept.

Installed

  1. Run the installer from the Windows account you run shows from. Windows asks for an administrator's approval once. Its pages are described in Laptops: the installer.
  2. On its last page, The first admin account, you may make the first admin account now. Leave it empty to make it later at the laptop, with the token.
  3. Open Start → AGMessage → Open AGMessage. It opens http://localhost:3023 in your browser.

The admin token and Admin login

The admin token is 16 characters that AGMessage makes each time it starts, so a restart means a new one.

  • Portable: it is the Token: line in the black window, under Admin login (only from this host laptop):
  • Installed: Start → AGMessage → Show the admin token. Only the laptop's admin, and an account given the token right, can read it.
  1. On the AGMessage laptop itself, open http://localhost:3023/admin.
  2. Type the token in Admin token, then press Unlock admin.

△ Watch for The token works only on the laptop, opened as localhost. From any other device, and from the laptop's own LAN address, it is refused: Admin login is only allowed on the host laptop. Use an admin account there instead. After five wrong tokens, each further wrong one is refused for a minute; the right one still opens it.

The first admin account

While AGMessage has no accounts, its sign-in page shows Create the first admin. It works only on the AGMessage laptop, with the token.

  1. On the laptop, open http://localhost:3023.
  2. Fill in Admin token, Your name, Username and Password, then press Create admin account.
  3. It signs you in and opens the halls board. Its Accounts link makes everyone else's account: People: add a person. Later, sign in with it on the Sign in tab.

A password is 10 to 128 characters; a few words together is easy to type and hard to guess. It may not be a common password, one character repeated, or contain the username or the person's name.

The admin page

The admin page (/admin.html) opens for the token at the laptop, or for an account allowed app settings, from any device on the venue network. Its header has New hall, the theme button and Logout. On the left, Halls lists each hall and its rooms; choose one to watch it. Under the hall you watch come its code, People in this room and Live messages. Then, in order:

After an upgrade, a strip offers Reload this page: the admin page reloads only when you say so, so nothing you are typing is lost.

Halls and rooms

Make a hall

  1. On the admin page press New hall (or the halls board's New hall, for an account that sets halls up).
  2. Type its name in Hall name (for example Hall 2). Where an earlier hall's Stagewatch link is kept, choose it in Its Stagewatch; otherwise it follows the default Stagewatch.
  3. Press Create hall. It gets a 6-character guest code, which crew without an account join with.

Add a room beside the Main room

  1. On the admin page, open the hall's ⋯ and choose New room in this hall…. (On the halls board: the hall's ⋯ → Set up… → + Add room.)
  2. Type its name in Room name (for example Legal) and press Make the room.
  3. A new room's guest code starts off: the admin, and the accounts given the room, go in. Turn it on from the room's ⋯ if guests should join with a code.

A hall's ⋯

On the admin page, each hall's ⋯ (or a right-click on it) offers:

  • Watch: its people and live messages, under the list.
  • Transcript and Minutes (an AI draft, posted pinned when you choose).
  • Roles & invites: codes and invite links.
  • New room in this hall…
  • Board members… (Members… on a side room): tick accounts into the room in one go. Offered to an account that creates accounts, not to the token.
  • May send in…: which rooms may send messages and files into this one.
  • Turn the code off… or Turn the code on, and New code…
  • Rename…, Clear messages…, and Close hall… (Remove room… on a side room).

△ Watch for Close hall… sends everyone out and deletes its saved history, and its Also delete the files shared only in this hall is ticked. To keep an event's halls, archive the event instead: After the event.

The halls board's Set up… on a hall holds its Name, its own Stagewatch (Address, Node key, Certificate fingerprint; leave them empty to follow the default) and its Rooms, each with its code and ⋯.

Codes and invite links

Each room has a code. Anyone with it joins on the sign-in page's Join with a code tab: in a hall's Main room as Backstage or as an Observer, and in a side room as a Member or an Observer.

△ Watch for A code alone never seats anyone On stage, in an open hall or not. Presenters and board members need the On stage invite link, an account seated On stage, or the admin moving their seat: seating the Board.

Roles & invites

  1. On the admin page, open the hall's ⋯ and choose Roles & invites. A panel opens under the hall you watch.
  2. To lock the hall's seats, tick On stage and Backstage seats need an invite link (anyone else joins as an observer) (on a side room, Member seats need an invite link (anyone else joins as an observer)).
  3. Copy each link with its 📋 Copy and send it only to that group: the On stage link to presenters and board members, and, while the seats are locked, the Backstage link to the crew. An open hall shows the On stage link alone.
  4. To stop a link admitting anyone new, press its 🔄 New On stage link (or the Backstage one). People already seated with the old link keep their seats, and the code stays.

△ Watch for An invite link is made from the address the admin page is open at. Opened at the laptop as localhost (as it is with the token), the copied link says localhost and will not open on a tablet: put the LAN address (or the internet link's) in its place before sending it, or copy it from the admin page opened at the LAN address with an admin account. Make a new On stage link after a shared device used it.

Turning a code off, and a new code

  • Turn the code off… asks how: Turn off (guests already in stay; nobody new joins) or Turn off and send them out. Accounts keep their way in either way. While the code is off, invite links admit nobody new.
  • New code… gives the room a new code. Guests in it stay; anyone joining later needs the new one, and the invite links made with the old code stop working, so send the new links from Roles & invites.

Backstage guests and web pages

In a locked hall, the tick Backstage guests may show web pages on people's pages lets guests who joined Backstage with the invite link show web pages, as accounts with that right do. It is off by default, the admin's alone, and needs the roles locked first; unlocking the hall turns it off.

People in a room

Watching a hall shows People in this room, one row a person: Name, Seat, Chat view, Clock or countdown, On stage and May forward to.

  • A guest's Seat is changed here (an account's follows its rights, on the Accounts page).
  • Chat view, the clock and the On stage switches are described in Tablets and phones.
  • A person's ⋯ also has Open their view (their page as they see it, to help them), Let them forward into another room, and Log out….

Screens

A screen is any browser that shows something for a hall: the projector PC, the lectern monitor, a foyer TV, a tablet in the green room. Each has a link of its own (/d/…), opened once in that browser and left there.

Changing what screens show needs Change what a hall's screens and people's pages show (Tech and up). Adding screens, their links, renaming and removing them need Create, rename, move and revoke screens, which the Admin and Project manager roles start with.

  1. On a hall page, open the header's ⋯ → Screens & pages…, Screens tab.
  2. Type a name such as Lectern monitor and press Add screen. Its link is copied.
  3. Open the link in that screen's browser. A double-click there makes it full screen.
  4. Optionally choose a Holding image: from the pictures shared in the hall and press Use it (None (black) keeps it black).

Tick the screens to change, then choose Holding, Countdown, Clock or Black, or type a message, choose ● Note, ▲ Soon or ■ Urgent (and Under the countdown) and press Show. Each screen's ⋯ has Identify, Copy link, Rename…, New link… and Remove….

△ Watch for Anyone with a screen's link sees that screen. Give it only to the machine that shows it, and choose New link… if it went further: the old link stops at once. Tablets and phones: screens covers the screen's own side.

Stagewatch, Patterns and PlayMap

The default Stagewatch

  1. In Stagewatch, make a node key: Settings → Remote → API keys.
  2. On the admin page, under 📡 Show network, type the Stagewatch address and its node key (and, if you have it, its certificate fingerprint), then press Link. A Stagewatch AGMessage hears on the network offers Use this address.
  3. Accept the key in Stagewatch. Until it does, the link is refused.

Halls without a Stagewatch of their own follow this one. A hall's own is set on the halls board's Set up…. If a Stagewatch's certificate changes, Health says so and the link waits until you choose Accept certificate… on its row.

Patterns and PlayMap

When AGMessage hears a Patterns or a PlayMap on the network, its row's ⋯ has Link…. It asks for its pairing token (Patterns: its Remote page, TRUST; PlayMap: its node settings, Network), which halls it is for (Every hall or one), and the first 16 characters or more of the fingerprint it shows on its own screen. A linked one has Set up…, Confirm fingerprint… and Unlink….

AI drafts

Under ✨ AI drafts, paste an Anthropic key in Anthropic API key (sk-ant-…) and press Save key. AI drafts are always a draft that a person edits and sends. Without a key, every AI act is greyed with the reason; everything else works. AI drafts, the internet link and the installed laptop's look-up of a new release are the only parts that need the internet.

Encrypted connections

AGMessage serves HTTPS on the same port as HTTP, with a certificate of its own. Each device trusts it once; after that, people open AGMessage with https:// instead of http://, same address and port. A tablet needs HTTPS to keep its screen awake.

  1. On each device, open /tls on AGMessage's address (for example https://192.168.1.42:3023/tls).
  2. Check that its SHA-256 fingerprint matches the Fingerprint: under 🔒 Encrypted connections on the admin page.
  3. Press Download the certificate and follow the steps /tls gives for that device (Windows, macOS, iPhone and iPad, Android).

The tick Require HTTPS from other devices (plain HTTP keeps working on this laptop, and for the Cloudflare tunnel) sends every other device to HTTPS.

△ Watch for With Require HTTPS on, a page or screen opened with an http:// link from another device is sent to the same address over https://; a device that has not trusted the certificate then shows the browser's certificate warning instead, and a screen already open over http:// says This AGMessage requires HTTPS — open it with https:// (see /tls). Trust the certificate on each screen and tablet first. New certificate means every device trusts it again.

The internet link

Phones off the venue network (on mobile data, in another building) join through a Cloudflare quick tunnel, from 🌐 Remote access (Cloudflare tunnel) on the admin page.

  1. Turn it on with the card's switch (or Turn on in its ⋯). While it starts, it reads Starting….
  2. Send the address under Public URL — share with remote users: to the people off-site (Copy address in its ⋯). With it and a hall's guest code, they join.
  3. Before doors, press Check again and walk one phone on mobile data through it.
  • It stays on until the end of the show day, 06:00 by the laptop's clock, or the time Tunnel until… gives.
  • It has 150 places at once, half of them at most from one network. The card counts them and the day's refusals.
  • Turn off… asks first: everyone who joined through it is cut off, and the address stops working.
  • Accounts with admin rights sign in through it only when Let accounts with admin rights sign in through the Cloudflare tunnel (off: admins sign in on the venue network only) is ticked under Accounts and access.

△ Watch for A quick tunnel's address is new each time AGMessage starts. If AGMessage restarts during the day, it turns the link on again with a new address, said on the card: send the new address to the people off-site, since the old one no longer works. Invite links copied for remote people need the public address in place of localhost.

A show day

Before doors

  1. On 💻 This laptop, read Addresses, Network, Firewall, Sleep on mains and Lid closed on mains. A firewall with no rule for the network's profile means phones there may not reach AGMessage: the firewall and networks. Set closing the lid to do nothing on mains.
  2. Send each On stage link from Roles & invites to its presenters and board members, and, in a locked hall, its Backstage link to the crew.
  3. Open each screen's link, and check each shows what it should.
  4. On a Board tablet, open a hall On stage and check its clock, Help and a file's Look: what to check on a device.
  5. With the internet link on, read its check and walk one phone on mobile data.
  6. After an upgrade, read Pages on This laptop: every open page and screen is on this build, or which still reload.
  7. Copy the audit log's signing key (🩺 Health, 📋 Copy) into the show's paperwork, and compare it at each start.

During

  • Help requests show on the halls board under Needs help, with On my way and Resolved.
  • While a hall is live, AGMessage keeps the laptop from idle sleep (This laptop: Kept awake). The lid and the power button still do what the power plan says.
  • A page that loses the connection comes back by itself; what someone wrote waits and is sent once.

After

  • Export the audit log at the end of each show day (🩺 Health → Export…) and keep the export off the laptop.
  • Turn the internet link off.
  • After the last day, archive the event.

After the event

Archiving keeps everything of an event (its halls, messages, files, help requests, screens, accounts and what was shown) in the data folder's archive, never deleted silently, and begins the next one. Only the admin may archive.

  1. Under 🗄 Event, press Archive this event….
  2. Choose What comes next: Start fresh: no halls, screens or accounts, Copy this event's settings and structure, a copy of an archived event's, or continuing one.
  3. Name this event for its archive if it has no name, and type the new event's name to confirm. Choose whether to keep the screens' links (for screens of your own kit) and whether to split the audit log there too.
  4. Press Archive.

△ Watch for Archiving ends every sign-in, the token's too: everyone signs in again or joins with the new codes, and the admin page reloads. A copy gives every room a new code and carries no invite link over. After Start fresh: no halls, screens or accounts, the token makes the first admin account again.

Each archived event's row offers Continue this event…, Copy this event… and Delete this archive's contents…, which works only at the laptop, with the token typed.
