            How a remote user joins via Cloudflare
            1. cloudflared is bundled with this server — no separate install needed. The portable ZIP ships bin/cloudflared.exe alongside node/node.exe. (If you ever need a manual copy, you can grab one from github.com/cloudflare/cloudflared.)
            2. Toggle Remote access above to ON. The server spawns cloudflared tunnel --url http://localhost:<port> for you and watches its output for the public URL.
            3. Once the URL appears, click 📋 Copy and share it with each remote user, along with the room's guest code.
            4. The remote user opens the URL in any browser, enters the code, their name and their seat, and joins as they would on the venue's network.
            5. It stays on until the end of the show day (06:00 by this laptop's clock; turned on after 05:00, 06:00 the next day), or the time Tunnel until… sets: then it is turned off and stays off. If AGMessage starts again before then, the link is turned on again with a new address, which this card says: send the new one to remote people. If it could not be turned on again (the laptop not online yet), this card says so: turn it on once the laptop is online. Turn it off sooner when the show is over.

            For a show with remote people, a named Cloudflare Tunnel keeps one address across restarts: run it yourself (cloudflared, with a stable subdomain, pointing at this laptop's port) and leave this toggle off — the server doesn't depend on it.

              Split the audit log

              Each event archived leaves an archive point in the audit log. Splitting at one moves the entries before it, whole files, into a signed archive in this laptop's data folder (audit-archive). Nothing is deleted: the check then starts at the point and names the archive, the archive is checked on its own, and every export still carries it. Leave the archive where it is: one moved or removed reads ✕ until it is accepted with the token.
